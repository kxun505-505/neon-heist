# 关卡准则和验收标准

这份文档是关卡生成器的规格说明，任何人或任何模型做关卡都按它来。规则代码只有一份：
- `src/core.js`：机制、碰撞、求解器。游戏和生成器共用。
- `src/layout.js`：排版，以及避让陪玩角色。游戏和生成器共用。
- `tools/levelgen/levelgen.js`：生成和验收。验收的数字都在文件开头的 `RULES` 里。
- `tools/levelgen/curve.js`：1-100 关每关的目标。
- 批量生成（`batch` / `poolcheck`，结果放在 `levels-pool/`）见 `docs/codex-handoff.md`。

改了这里的任何数字，要同时改代码里对应的地方，反过来也一样。

## 1. 怎么跑（只需要 Node 16 以上，不用装依赖）

```sh
node tools/levelgen/cli.js check              # 验收 src/levels.js 的全部关卡，全过退出码为 0
node tools/levelgen/cli.js curve              # 看 1-100 关的目标
node tools/levelgen/cli.js batch --from 11 --to 100 --jobs 8   # 批量生成到 levels-pool/，可断点续跑
node tools/levelgen/cli.js poolcheck --to 100                  # src/levels.js + levels-pool/ 整体验收
node tools/levelgen/cli.js gen --level 12 --seeds 150 --out /tmp/L12.json
node tools/levelgen/cli.js apply --level 12 --file /tmp/L12.json --name 中文名 --en "ENGLISH NAME" --tip "提示"
```

- 没有 Node 时，用 `tools/verify.sh` 跑浏览器版验收。它调用同一份代码，需要本机装有 Chrome。
- 生成某一关时，会读取 `src/levels.js` 里它前面的关卡，用来做跨关卡的检查，所以要按关卡顺序生成。
- `gen` 找不到合格的关卡时，会打印淘汰原因的统计。可以试这几种办法：加大 `--seeds`；换 `--seed0`；调整 `curve.js` 里这一关的 `grow` 参数；最后才考虑放宽范围。
- 新关卡写进 `src/levels.js` 以后，还要做这些事：
  - 在 `src/i18n.js` 里给 6 种语言补上这一关的提示（`tips` 数组，按关卡顺序）。
  - 在 `src/chapters.js` 里补上奖励素材的路径，没有素材就填 `null`。
  - 跑第 6 节的发布前检查。

## 2. 关卡数据格式

格式见 `src/levels.js` 开头的注释。坐标是逻辑像素，原点在棋盘中心，y 轴朝下。角度单位是度，0° 指向右，顺时针为正。

## 3. 生成准则（怎么设计）

**G1 结构**
- 主环伸出杆子，扣住被扣环，用 `links: [主环, 被扣环]` 表示。主环关系不能成环。
- 根部要有闭合环，或者没有人扣着的 C 环。
- 一个环身上最多 4 条连接（杆和夹套加起来）。
- 被扣环要留得出缺口的位置：所有连接之间至少要有一段 140° 的空弧。
- 一个零件被两个主环扣住（桥）时，至少一个主环要是根环。原因是：主环扣着东西时转不动，非根的主环也就永远飞不走；根环可以在它扣着的连接全部松开时，连同这些连接一起飞走。两个主环都不是根，就成了死结。

**G2 几何**
- 环的半径一般是 36-42。大环可以到 100 以上，里面可以套小环或直杆。
- 杆长 15-18。环和环之间不重叠，套在里面的情况除外。
- 缺口名义宽度 96-108°，开局时不能落在任何夹套上。
- 凸钉长在实心管子上，不靠近缺口和杆，开局不能顶着别的零件。

**G3 排版**
- 布局按竖屏设计，右下角留给陪玩角色。
- 棋盘在参考屏 390×844 上缩放后，所有零件占的地方都不能压到角色轮廓。“占的地方”包括转动时凸钉和空夹套扫过的范围。
- 程序生成时，格子直接避开角色。

**G4 难度靠推理，不靠堆零件**
- 加难的办法按优先顺序是：
  1. 第一步陷阱：看起来能走、走了却变难或者走不通。
  2. 凸钉卡位。
  3. 空夹套挡路。
  4. 桥：一个零件同时被两个主环扣住。
  5. 先后顺序更长的链。
  6. 要拖两次以上的零件。
- 不要靠缩小环、多塞零件来加难。

**G5 节奏**
- 每关最多 1 个新机制，只在普通关引入，并配一句提示。
- 困难关只组合已经学过的机制。
- 困难关后面那一关可以轻一点。

**G6 原创**
- 不照搬原作任何一关的布局，只对标难度。
- 结构模板和程序生成都是自己设计的。

## 4. 验收标准（全部满足才算合格）

都在参考屏 390×844（iPhone 12-15 的 CSS 尺寸）上计算。

| 编号 | 项目 | 标准 |
|---|---|---|
| A | 合法 | `RRCore.validate` 没有报错。它检查：杆长 ≥ 8；杆根不在主环缺口里；夹套和套筒开局没有松开；凸钉不在缺口里、不贴着连接；开局没有碰撞，也没有零件直接飞走；每个零件至少有一条连接；环不重叠。另外主环关系不能成环。 |
| B | 可解 | 广度优先求解器在深度 26、60000 个状态以内求出最少步数（par）。求不出来时，快速求解器要在 120000 个状态以内找到解。这种关的 par 标 `~`，生成时降低优先级。另外，开局时游戏里的提示按钮要能给出下一步（`RRCore.hintMove`，预算用 `RRCore.hintBudget`）。 |
| C | 尺寸 | 最小环半径 ≥ **27.5px**，这是第 4 关最小环的实测值。管子粗细 ≥ **9px**。困难关两项都可以降到 90%，也就是 24.8px 和 8.1px。 |
| D | 不挡角色 | 零件占的地方加 8px 余量，不压到这一章角色立绘的轮廓（`chapters.js` 里的 `girl.mask`）。另外，`tools/layout.html` 会在 6 种屏幕尺寸下打开真实页面检查：不压到角色，不出屏幕，不压到 HUD 和按钮；参考屏的缩放和 `layout.js` 的计算误差在 0.5% 以内。 |
| E | 难度 | 零件数、par 都在 `curve.js` 给这一关的范围里；第一步陷阱比例不低于目标；`hard` 标记和关卡号一致，每 5 关的最后一关是困难关。 |
| F | 节奏 | 零件数最多比前面所有关里最多的那关多 2 个，第 1-5 关放宽到多 3 个。每关最多 1 个新机制，第 1-4 关最多 2 个。困难关不引入新机制。引入新机制的关要有 `tip`。结构指纹不能和前面任何一关完全一样。困难关的难度指数不低于同组前面的普通关。 |

### 指标的定义

- **par**：最少拖动次数。一次拖动指按住一个零件，朝一个方向转到底或滑到底。
- **第一步陷阱比例 trap**：所有不同的第一步里，走完以后不能再用 par−1 步解开的比例。
- **死局 dead**：走完以后彻底解不开的第一步有几个。
- **回头 revisit**：最优解里需要拖不止一次的零件个数。
- **难度指数 D** = par + 6×trap + 2×revisit + （有死局时再加 3）。
- **机制标签**：`chain`（3 层以上的链）、`closed`（闭合环）、`knob`（凸钉）、`bridge`（桥）、`bar`（直杆）、`nest`（套在大环里）。
